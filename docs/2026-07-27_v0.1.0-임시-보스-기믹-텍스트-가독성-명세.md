# v0.1.0 임시 보스 기믹·텍스트 가독성 명세

- 작성일: 2026-07-27
- 대상: `Prototype_Casual_Rogue` 프로토타입
- 목적: 보스 반복 타격 수단과 갇힘 방지 규칙을 시험하고, 플레이 중 설명 텍스트의 가독성을 개선한다.
- 개발 범위: 이 문서를 프로토타입의 마지막 개발 전달 범위로 삼는다. 반영·검수 이후에는 신규 기능을 추가하지 않고 포트폴리오 문서 작업으로 전환한다.
- 상태:
  - 보스 신규 기믹: **임시 테스트**
  - 텍스트 크기·굵기·강조 규칙: **프로토타입 적용 기준**

## 최상단 변경 요약

| 우선순위 | 변경 사항 | 적용 기준 |

## 수정 순서

1. 보스 1행동 1피격 제한을 공통 규칙으로 고정한다.
2. `돌진 충돌`과 `탈출 이동`을 보스 기본 규칙에 추가한다.
3. `증폭 방어막`을 활성 변형 목록에서 제외한다.
4. 신규 변형 2종과 기존 `증원 소환`을 스테이지별로 고정 배치한다.
5. 모든 보스 피격·이동 결과를 실행 전에 미리 표시한다.
6. 설명 문구를 축약하고 글자 크기·굵기·강조 규칙을 적용한다.
7. 중복 피격, 갇힘, 저장 후 재실행을 QA한다.

## 최소 완료 기준

- 보스가 어떤 조합에서도 영구적으로 갇히지 않는다.
- 한 번의 룬 행동으로 같은 보스가 두 번 이상 피해를 받지 않는다.
- 충돌, 약점, 수호 연결의 예상 결과와 실제 결과가 일치한다.
- 보스 피격 원인을 화면만 보고 구분할 수 있다.
- 플레이 중 필수 설명은 확대 없이 읽을 수 있고 최대 2줄을 넘지 않는다.
- 중요한 상태를 색상만으로 구분하지 않는다.

## 1. 공통 보스 규칙

### 1-1. 1행동 1피격

- 한 번의 룬 행동에서 보스가 받을 수 있는 피해는 최대 1회다.
- 직접 공격, 끝점 참격, 약점 표식, 수호 연결, 돌진 충돌이 겹쳐도 추가 피해는 발생하지 않는다.
- 먼저 처리된 공격으로 이미 피격했다면 뒤의 피격 판정은 피해 없이 연출과 상태만 정리한다.
- 보스 처치에 경험치나 추가 보상을 별도로 지급하는 규칙은 이번 명세에 포함하지 않는다.

### 1-2. 보스 이동 예약

- 보스는 일반 몬스터보다 먼저 이동 목적지를 예약한다.
- 예약 결과는 해당 턴 동안 고정하며 저장 후 다시 열어도 바뀌지 않는다.
- 공격과 능력 판정이 끝난 뒤 보스 이동을 처리한다.

## 2. 보스 기본 기믹

### 2-1. 돌진 충돌 — 임시 테스트

#### 발동

- 플레이어가 룬을 놓아 보스의 **예약 이동 칸을 새 룬 흔적으로 막으면** 발동한다.

#### 결과

- 보스가 룬 흔적에 충돌하고 피해 1회를 받는다.
- 보스는 현재 칸에 남으며 막힌 목적지로 이동하지 않는다.
- 해당 행동에서 보스가 이미 피해를 받았다면 추가 피해는 없지만 이동은 정지한다.
- 기존 룬 흔적이나 오염 때문에 막힌 경우에는 돌진 충돌 피해를 주지 않는다.

#### 표시

- 룬 배치 확정 전, 예약 이동 칸과 충돌 예상 지점을 표시한다.
- 충돌로 처치될 경우 보스의 알파값을 낮추고 추후 처치 아이콘을 붙일 수 있는 공간을 남긴다.
- 미리보기와 실제 결과가 다르면 기능 실패로 처리한다.

### 2-2. 탈출 이동 — 임시 테스트

#### 발동

- 턴 시작 시 보스가 이동할 수 있는 인접 칸이 하나도 없을 때 발동한다.
- `층 초기화`는 QA 기능이므로 정상 플레이의 해결책으로 사용하지 않는다.

#### 처리

1. 보스 주변의 제거 가능한 방해물 후보를 찾는다.
2. 우선순위는 `기존 룬 흔적 > 오염 > 일반 몬스터`다.
3. 같은 우선순위의 후보가 여러 개면 무작위로 1개를 선택하고 즉시 결과를 고정·저장한다.
4. 선택한 방해물에 균열 표시와 특수 이동 화살표를 보여준다.
5. 이동 단계에서 해당 방해물 1개를 제거하고 보스가 그 칸으로 이동한다.

#### 예외

- 탈출 이동 자체로 보스는 피해를 받지 않는다.
- 일반 몬스터를 제거한 경우 경험치와 처치 보상을 지급하지 않는다.
- 탈출 이동으로 제거한 룬 흔적은 플레이어의 신규 룬 행동으로 취급하지 않는다.
- 후보 자체가 없는 예외 상황은 QA 오류로 기록한다.

## 3. 보스 변형

### 3-1. 활성 목록

| 변형 | 상태 | 핵심 역할 |
|---|---|---|
| 약점 표식 | 신규·임시 | 퍼즐 경로로 추가 타격 기회 제공 |
| 수호 연결 | 신규·임시 | 일반 몬스터 처치와 보스 공격을 연결 |
| 증원 소환 | 기존·임시 배치 | 보스 피격 뒤 보드 압박 추가 |
| 증폭 방어막 | 비활성 | 프로토타입 출현 목록에서 제외 |

- 보스 1체에는 변형을 최대 1개만 적용한다.
- 이번 버전에서는 효과 검증을 위해 무작위 배정하지 않는다.
- `증폭 방어막`의 기존 문서 기록은 삭제하지 않는다.

### 3-2. 약점 표식 — 임시 테스트

#### 생성

- 매 턴 보스 인접 칸 중 유효한 칸 1개를 무작위로 선택한다.
- 보스 현재 칸, 예약 이동 칸, 룬 흔적, 오염, 점유 칸은 제외한다.
- 남은 룬과 현재 보드 상태에서 실제로 통과 가능한 칸만 후보가 된다.
- 선택 결과는 해당 턴 동안 고정·저장한다.

#### 발동과 피해

- 플레이어가 그은 룬 경로가 약점 표식을 직접 통과하면 보스가 피해 1회를 받는다.
- 끝점 참격 등 능력 범위만 표식에 닿은 경우에는 발동하지 않는다.
- 같은 행동의 직접 보스 공격과 겹쳐도 총 피해는 1회다.
- 약점 표식 피해에는 경험치를 지급하지 않는다.
- 다음 턴에 새 표식을 선정한다.

#### 후보가 없을 때

- 그 턴에는 약점 표식을 생성하지 않는다.
- 불가능한 칸에 표식을 강제로 생성하지 않는다.
- QA 기록에 `약점 후보 없음` 횟수를 남긴다.

### 3-3. 수호 연결 — 임시 테스트

#### 지정

- 보스 플로어 시작 시 기존 일반 몬스터 중 1체를 무작위로 지정한다.
- 지정 결과는 고정·저장하며, 연결 대상이 사라져도 새 대상을 지정하지 않는다.
- 대상과 보스 사이에 표식과 연결선을 표시한다.

#### 발동과 피해

- 연결된 일반 몬스터가 직접 공격 또는 능력으로 처치되면 보스가 피해 1회를 받는다.
- 직접 처치 경험치는 기존 규칙을 따르고, 능력 처치는 기존처럼 경험치를 지급하지 않는다.
- 보스로 전달된 피해에는 별도 경험치를 지급하지 않는다.
- 같은 행동에서 보스가 먼저 피격됐다면 추가 피해는 없으며 연결 효과는 소모된다.
- 연결 대상이 보스의 탈출 이동에 의해 제거되면 피해와 보상을 모두 발생시키지 않는다.

### 3-4. 증원 소환 — 기존 규칙 유지

- 보스가 피격 후 생존하면 보스 이동 뒤 인접한 합법 칸에 방어막 없는 일반 몬스터 1체를 소환한다.
- 한 행동에 최대 1회만 발동하며 보스가 처치된 행동에는 발동하지 않는다.
- 소환 위치는 사전에 반투명 형태로 표시하고 무작위 결과를 고정·저장한다.
- 새로 소환된 몬스터는 다음 턴부터 이동과 오염 생성을 시작한다.

## 4. 임시 스테이지 배치

| 스테이지 | 보스 변형 |
|---|---|
| 스테이지 1 | 약점 표식 |
| 스테이지 2 | 수호 연결 |
| 스테이지 3 | 증원 소환 |

- 고정 배치는 각 효과를 독립적으로 검증하기 위한 임시 규칙이다.
- 세 효과의 이해도와 난도가 검증된 뒤에만 무작위 조합을 재검토한다.

## 5. 처리 순서

1. 직접 공격 및 약점 표식
2. 끝점 참격
3. 유혹 — 일반 몬스터만 적용
4. 도탄 — 일반 몬스터만 적용
5. 수호 연결 피해 전달
6. 보스 이동, 돌진 충돌 또는 탈출 이동
7. 일반 몬스터 이동 및 오염 생성
8. 증원 소환
9. 클리어·실패 판정
10. 저장 및 레벨업 처리

- 어느 단계에서든 보스가 이미 피격했다면 이후 보스 피해는 0으로 처리한다.
- 보스 처치가 확정되면 이후 보스 이동과 증원 소환은 실행하지 않는다.

## 6. 보스 정보 표시

- 스테이지 진입 시 적용된 보스 변형 이름과 핵심 효과를 먼저 알린다.
- 플레이 중 화면 상단에는 `변형 이름 · 핵심 효과` 형식의 한 줄만 유지한다.
- 상세 규칙은 클릭 가능한 도움말 또는 상세 설명에서 제공한다.
- 보스의 방어막은 기존 기준대로 굵은 하늘색 외곽선과 낮은 알파값의 하늘색 패널로 표시한다.
- 예약 이동, 약점 표식, 수호 연결, 충돌 예정은 서로 형태가 달라야 한다.
- 정보 우선순위는 `처치 예정 > 이동 화살표 > 오염 예정`을 유지한다.

## 7. 텍스트 간소화 및 가독성

### 7-1. 글자 크기와 굵기

| 용도 | 크기 | 굵기 |
|---|---:|---:|
| 화면·모달 제목 | 22–26px | 800 |
| 주요 버튼·능력 카드 이름 | 14px | 700 |
| 일반 설명·모달 본문 | 14px | 600 |
| 상태·보스 변형 | 13px | 700 |
| 보조 라벨·아이콘 설명 | 12px | 600 |

- 플레이에 필요한 정보는 12px 미만으로 표시하지 않는다.
- 모든 문장을 800–900으로 만들지 않는다. 제목, 핵심어, 본문의 위계를 유지한다.
- 버튼과 클릭 가능한 항목의 명칭은 최소 700으로 표시한다.

### 7-2. 문장 간소화

- 플레이 화면의 설명은 **핵심 문장 1개, 최대 2줄**로 제한한다.
- 전체 규칙은 도움말이나 상세 설명으로 이동한다.
- 아이콘과 숫자로 이미 전달한 내용을 문장으로 반복하지 않는다.
- 능력 카드는 `이름 / 단계 변화 / 현재 효과 1줄`만 기본 노출한다.
- 결과 정보는 문장보다 `직접 2 · 능력 1 · 오염 1/6`처럼 짧게 표시한다.

### 7-3. 중요 부분 강조

- 한 카드나 안내 블록에서 가장 중요한 강조 문장은 1개만 둔다.
- 다음 요소만 선택적으로 강조한다.
  - 발동 조건: `피격 후 생존`, `룬 경로가 직접 통과`
  - 핵심 수치: `1체`, `방어막 2`, `필요 타격 3`
  - 상태 변화: `사용 가능`, `사용 완료`, `LV.1 → LV.2`
- 강조는 굵기 700–800과 강조색 또는 짧은 배경 토큰을 함께 사용한다.
- 긴 문장 전체를 굵게 표시하지 않는다.
- 위험, 차단, 사용 불가 상태는 아이콘과 문구를 함께 사용하며 색상만으로 전달하지 않는다.
- 레벨업 카드는 `능력 이름 800 / 단계 변화 700·강조색 / 효과 설명 600` 순으로 구분한다.
- 보스 상단 정보는 `변형 이름 800·강조색 / 발동 조건·수치 700 / 보조 설명 600`으로 구분한다.

### 7-4. 문구 예시

- `약점 표식 · 표식을 직접 통과하면 보스 피격`
- `수호 연결 · 연결된 몬스터 처치 시 보스 피격`
- `증원 소환 · 피격 후 생존 시 1체`
- `유혹 · LV.1 → LV.2`
- `충돌 대상 1체 → 2체`
- `직접 2 · 능력 1 · 오염 1/6`

## 8. 저장과 무작위 결과

- 보스 이동 목적지, 탈출 대상, 약점 표식, 수호 연결 대상, 증원 위치는 결정 즉시 저장한다.
- 앱 종료 후 재진입해도 결과가 다시 추첨되지 않아야 한다.
- 미리보기 단계와 실행 단계는 같은 저장 결과를 사용한다.

## 9. QA 항목

### 보스 기믹

- [ ] 보스 예약 칸을 새 룬으로 막으면 충돌 피해와 이동 정지가 모두 발생한다.
- [ ] 이미 보스를 공격한 행동에서 충돌·약점·연결이 겹쳐도 추가 피해가 없다.
- [ ] 보스가 완전히 갇혀도 다음 이동 단계에 탈출한다.
- [ ] 탈출로 일반 몬스터가 제거될 때 경험치와 수호 연결 피해가 발생하지 않는다.
- [ ] 약점 표식이 합법적인 경로 칸에만 생성된다.
- [ ] 수호 연결 대상과 연결선이 저장 후에도 유지된다.
- [ ] 보스 처치 행동에서는 이동과 증원 소환이 발생하지 않는다.
- [ ] 저장 후 재진입으로 무작위 결과를 바꿀 수 없다.

### 텍스트

- [ ] 화면 확대 없이 제목, 버튼, 상태, 설명을 읽을 수 있다.
- [ ] 플레이 중 핵심 설명이 2줄을 넘지 않는다.
- [ ] 긴 문장 전체가 굵게 처리된 영역이 없다.
- [ ] 발동 조건과 핵심 수치가 본문보다 먼저 눈에 들어온다.
- [ ] 중요한 상태를 색상만으로 구분하지 않는다.
- [ ] 데스크톱과 모바일에서 잘림, 겹침, 버튼 높이 변경 문제가 없다.

## 10. 임시 기믹의 유지·폐기 판단 자료

- 보스 피격 출처별 사용 횟수를 기록한다: 직접 공격, 끝점 참격, 돌진 충돌, 약점 표식, 수호 연결.
- `약점 후보 없음` 발생 횟수를 기록한다.
- 탈출 이동 발생 횟수와 제거한 장애물 종류를 기록한다.
- 미리보기와 실제 결과가 한 번이라도 다르면 해당 기믹을 완료 처리하지 않는다.
- 현재 보스 타격 문제가 남았다는 이유만으로 스테이지 3의 방어막을 즉시 줄이지 않는다. 신규 타격 수단을 먼저 검증한다.
- 포트폴리오 작성 단계에서는 검수 결과를 설계 의도와 트레이드오프의 근거로 사용하며, 결과를 이유로 새 기능 개발을 재개하지 않는다.
