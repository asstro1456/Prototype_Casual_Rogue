# Project TTT 저격 포트폴리오 설계안

## 1. 지원 포지션 해석

이 포지션은 레벨·콘텐츠 한 분야의 전문 기획자보다 다음에 가깝다.

> 소규모 신규 개발팀에서 시스템·콘텐츠·밸런스를 연결하고, Unity와 데이터 시트로 실제 제작까지 밀어붙이는 서브컬처 캐주얼 로그라이크 제너럴리스트 기획자

평가의 중심은 아이디어의 크기보다 다음 네 가지다.

1. 여러 기획 영역을 하나의 플레이 경험으로 연결하는가
2. 아이디어를 데이터와 제작 단위로 구체화할 수 있는가
3. 테스트 결과를 근거로 수정할 수 있는가
4. 서브컬처·로그라이크·모바일 시장을 실제 플레이 경험으로 이해하는가

## 3. 포트폴리오 전체 전략

### 프로젝트 A — 기존 프로젝트 묶음

증명할 것:

- 로그라이트: 시스템·콘텐츠·방 진행 규칙
- 냥냥스타: 콘텐츠 제안·QA·테스트
- UT: Unity·서브컬처·UX·상태/예외
- 리듬게임: 신규 개발·PM·스테이지 난이도
- VN: 데이터 구조·엔진 적용·오류 검수

다루지 않을 것:

- 본인이 담당하지 않은 시스템·콘텐츠
- 구현되지 않은 개인 확장안
- 정량 기록이 없는 테스트의 효과 수치
- AI 생성 코드를 독립 개발 역량으로 표현하는 문구

### 프로젝트 B — 신규 개인작

기존 프로젝트에서 비어 있는 것만 증명한다.

- 선택 간 가치 비교가 보이는 밸런스
- 트렌드 분석
- 동일 기준의 플레이테스트와 수정 전후
- 개인이 처음부터 끝까지 소유한 기획

두 프로젝트를 합치면 다음 문장이 성립해야 한다.

> 협업 프로젝트에서 로그라이트 시스템·Unity·콘텐츠·QA를 경험했고, 개인 프로젝트에서는 하나의 로그라이크 콘텐츠를 트렌드 분석·밸런스·데이터·동일 지표 테스트까지 완결했다.

## 4. 최소 고효율 개인작

### 제목

**프리즘 리콜**

### 한 줄 설명

화면 아래의 색 정령을 탭해 적의 결정 외피를 공격하고, 4라운드 동안 색 계열 능력을 조합하는 서브컬처 하이브리드 캐주얼 로그라이크 프로토타입.

### 이 콘셉트를 선택하는 이유

- 사용자가 자주 플레이한 `Jelly Busters`의 색 선택·표면 제거를 단일 코어 조작으로 사용한다.
- 규칙을 `아래에서 색을 골라 같은 색의 표면을 지운다`는 한 문장으로 설명할 수 있다.
- 탭과 색 선택 중심으로 모바일 캐주얼의 낮은 조작·인지 부담을 유지한다.
- 결정 외피 제거 자체를 공격으로 표현해 별도의 전투 화면이나 조작을 추가하지 않는다.
- 어떤 색을 우선 제거했는지에 따라 런 능력 후보가 달라져 캐주얼 조작이 로그라이크 빌드 선택이 된다.
- 4라운드 블록 안에서 `학습→능력 획득→응용→종합 검증`을 완결한다.
- 3D 구현이나 몬스터 AI 없이도 시스템·콘텐츠·밸런스 데이터를 설계하고 테스트할 수 있다.
- Project TTT의 로그라이크·캐주얼·서브컬처 요구에 직접 대응하면서 특정 게임의 탑 구조를 복제하지 않는다.

## 6. 현재 구현 규칙

### 결정판과 색 정령

- 결정판은 `5×5`셀이다. 각 셀은 1~3층의 색 결정을 가진다.
- 셀에서 현재 가장 위에 있는 색만 노출된다.
- 하단에는 색 정령 후보 3개가 표시된다.
- 색 정령 하나를 탭하면 결정판 전체에서 같은 색으로 노출된 결정을 모두 1층씩 제거한다.
- 사용한 후보 한 칸은 현재 노출된 색 중 하나로 무작위 보충된다. 남은 후보가 이미 사라진 색이라면 눌러도 소모되지 않는다.
- 후보 3개 중 최소 하나는 현재 공격 가능한 색이 되도록 보정한다.

### 반격과 실패

- 시작 보호막은 3칸이며 네 라운드 동안 유지된다.
- 유효한 색 정령을 한 번 사용할 때마다 반격 게이지가 1칸 증가한다.
- R1·R2는 6탭, R3·R4는 5탭에 반격이 발생해 보호막이 1칸 감소한다.
- 반격 기준을 채운 마지막 탭으로 모든 결정을 제거했다면 반격은 취소된다.
- 결정이 남은 상태에서 보호막이 0이 되면 블록 실패다.
- 보호막 회복은 현재 프로토타입에 구현하지 않았다.

### 능력

| 능력 | 실제 구현 효과 |
|---|---|
| 적색 연쇄 | 적색 공격 시 능력 레벨만큼 무작위 다른 색 노출 결정을 추가 제거 |
| 청색 재배열 | 라운드마다 능력 레벨만큼 후보 3개를 재추첨 |
| 황색 보호 | 라운드마다 능력 레벨만큼 황색 공격의 반격 게이지 증가를 무효화 |

- R1·R3 종료 후 적·청·황 능력 3개가 항상 모두 제시된다.
- 누적 색 사용량과 다음 라운드의 전체 색 비중을 비교해 각 카드에 `현재 강화·다음 대응·빌드 전환` 역할표를 붙인다.
- 현재 강화와 다음 대응 색이 같으면 해당 카드에는 현재 강화가 우선 표시된다.
- 이미 가진 능력을 다시 고르면 최대 2레벨까지 강화된다.
- 능력과 색 사용량은 네 라운드 동안 유지된다.

### 4라운드 고정 흐름

```text
R1: 적·청 2색 온보딩, 반격 6탭
→ 능력 3택
R2: 3색 규칙 변형, 반격 6탭
→ 다음 라운드 예고
R3: 분산·압박형, 반격 5탭
→ 능력 3택
R4: 다층 종합 검증, 반격 5탭
→ 결과 등급·재시작
```

- 네 라운드의 결정 배치와 순서는 현재 고정이다.
- R1·R3에서는 능력 선택 화면, R2에서는 다음 라운드 예고 화면, R4에서는 결과 화면을 표시한다.
- 결과 화면에는 누적 사용량이 가장 높은 색, 총 탭 수, 잔여 보호막, 보유 능력 종류 수를 표시한다.
- 등급은 `S: 보호막 3·20탭 이하`, `A: 보호막 2 이상·25탭 이하`, `B: 보호막 1 이상`, `C: 그 외` 조건으로 계산한다.
- 실패 시 도달 라운드와 총 탭 수를 보여주고 처음부터 다시 시작한다.

### UI·피드백

- 모바일 세로 화면을 기준으로 라운드 트랙, 보호막, 반격 게이지, 결정판, 보유 능력, 색 정령 후보를 한 화면에 배치한다.
- 색상만으로 구분하지 않도록 `적색 ◆·청색 ●·황색 ▲` 기호를 함께 사용한다.
- 결정에는 현재 색과 남은 층 수를 표시하고, 전체 외피 제거율을 백분율 게이지로 제공한다.
- 유효 공격에는 화면 플래시와 제거 개수 문구를, 무효 후보에는 미소모 안내를 제공한다.
- 보유 능력은 색·이름·레벨 칩으로 표시하며 청색 능력 획득 시 후보 재배열 버튼을 노출한다.
- 시작 안내, 게임 방법, 능력 선택, 다음 라운드 예고, 성공 결과, 실패 결과를 모달 화면으로 구현했다.
- 캐릭터·결정·광원은 외부 리소스 없이 CSS 더미 그래픽으로 표현했다.

### 핵심 판단

> 지금 많이 노출된 색을 제거해 반격 전에 끝낼 것인가, 획득한 색 계열 능력의 효율을 우선할 것인가?

### 미구현 확장안

8라운드형은 현재 4라운드 블록을 두 번 연결하는 안이며 구현되지 않았다. 라운드 무작위화, 블록 사이 회복, 능력 6종 확장, 영구 성장과 경제 역시 현재 구현 범위가 아니다.

이 한 질문이 시스템·콘텐츠·밸런스를 관통해야 한다.

## 9. 가장 빠른 테스트 방식

현재 검증 대상은 외부 리소스 없이 제작한 로컬 HTML 프로토타입이다.

### 테스트 질문

1. 첫 행동에서 어떤 색을 선택했는가
2. 즉시 제거량과 원하는 색 능력 중 무엇을 우선했는가
3. 선택한 색과 표면 제거의 관계를 설명 없이 이해했는가
4. 획득한 런 능력이 다음 라운드의 탭 수와 피격에 미치는 영향을 인식했는가
5. 다시 플레이한다면 다른 색 능력을 선택하고 싶은가

### 최소 측정값

- 색상별 첫 선택률
- 빈 색 선택 시도 횟수
- 라운드별 평균 탭 수
- 라운드별 피격 횟수와 잔여 보호막
- 능력별 선택률
- 4라운드 도달률과 완료 시간
- 규칙 오해 횟수
- 재플레이 의향 5점 척도

테스트 결과가 없으면 결과 수치를 만들지 말고 `테스트 계획`이라고 명시한다.
