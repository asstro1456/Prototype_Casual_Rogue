# Project TTT 저격 포트폴리오 설계안

## 1. 지원 포지션 해석

이 포지션은 레벨·콘텐츠 한 분야의 전문 기획자보다 다음에 가깝다.

> 소규모 신규 개발팀에서 시스템·콘텐츠·밸런스를 연결하고, Unity와 데이터 시트로 실제 제작까지 밀어붙이는 서브컬처 캐주얼 로그라이크 제너럴리스트 기획자

평가의 중심은 아이디어의 크기보다 다음 네 가지다.

1. 여러 기획 영역을 하나의 플레이 경험으로 연결하는가
2. 아이디어를 데이터와 제작 단위로 구체화할 수 있는가
3. 테스트 결과를 근거로 수정할 수 있는가
4. 서브컬처·로그라이크·모바일 시장을 실제 플레이 경험으로 이해하는가

## 3. 포트폴리오 전체 전략

### 프로젝트 A — 기존 프로젝트 묶음

증명할 것:

- 로그라이트: 시스템·콘텐츠·방 진행 규칙
- 냥냥스타: 콘텐츠 제안·QA·테스트
- UT: Unity·서브컬처·UX·상태/예외
- 리듬게임: 신규 개발·PM·스테이지 난이도
- VN: 데이터 구조·엔진 적용·오류 검수

다루지 않을 것:

- 본인이 담당하지 않은 시스템·콘텐츠
- 구현되지 않은 개인 확장안
- 정량 기록이 없는 테스트의 효과 수치
- AI 생성 코드를 독립 개발 역량으로 표현하는 문구

### 프로젝트 B — 신규 개인작

기존 프로젝트에서 비어 있는 것만 증명한다.

- 선택 간 가치 비교가 보이는 밸런스
- 트렌드 분석
- 동일 기준의 플레이테스트와 수정 전후
- 개인이 처음부터 끝까지 소유한 기획

두 프로젝트를 합치면 다음 문장이 성립해야 한다.

> 협업 프로젝트에서 로그라이트 시스템·Unity·콘텐츠·QA를 경험했고, 개인 프로젝트에서는 하나의 로그라이크 콘텐츠를 트렌드 분석·밸런스·데이터·동일 지표 테스트까지 완결했다.

## 4. 최소 고효율 개인작

### 제목

**프리즘 리콜**

### 한 줄 설명

전사와 궁수 중 하나를 한 번 탭해 아래로 진격하는 적을 막는 4라운드 서브컬처 하이브리드 캐주얼 프로토타입.

### 이 콘셉트를 선택하는 이유

- 색과 기호는 속공형·중장형·위험형 적을 빠르게 식별하는 정보로 사용한다.
- 규칙을 `전사는 가까운 적을 넓게 베고, 궁수는 먼 위험 대상을 저격한다`는 한 문장으로 설명할 수 있다.
- 캐릭터 버튼 두 개 중 하나를 탭하는 방식으로 모바일 캐주얼의 낮은 조작 부담을 유지한다.
- 적의 하강과 방어선 돌파로 별도 반격 게이지 없이 시간 압박을 표현한다.
- 전사는 가까운 다수, 궁수는 먼 중장형을 담당해 캐릭터 비주얼과 시스템 판단을 연결한다.
- 4라운드 블록 안에서 `학습→능력 획득→응용→종합 검증`을 완결한다.
- 3D 구현이나 몬스터 AI 없이도 시스템·콘텐츠·밸런스 데이터를 설계하고 테스트할 수 있다.
- Project TTT의 로그라이크·캐주얼·서브컬처 요구에 직접 대응하면서 특정 게임의 탑 구조를 복제하지 않는다.

## 6. 현재 구현 규칙

### 전투선과 행동 후보

- 전투선은 `5열×5거리`로 구성한다.
- 라운드마다 고정된 적 분대가 상단에서 순차적으로 등장한다.
- 행동 후보를 사용할 때마다 생존한 적이 자신의 속도만큼 아래로 전진한다.
- 최하단을 돌파한 적은 유형에 따라 보호막에 1~2피해를 주고 이탈한다.
- 하단에는 전사와 궁수 버튼이 항상 표시된다.
- 전사는 가장 가까운 적이 있는 한 줄 전체에 1피해를 준다.
- 궁수는 거리 제한 없이 중장형을 우선 자동 조준해 한 명에게 2피해를 준다.
- 판의 `⚔·➶` 표시가 각 캐릭터의 현재 공격 대상을 알려준다.
- 플레이어는 추가 위치 선택 없이 캐릭터 하나만 탭한다.

### 적 유형과 실패

- 시작 보호막은 3칸이며 네 라운드 동안 유지된다.
- 일반형은 체력 1, 중장형은 체력 2다.
- 모든 적은 행동마다 1칸 전진한다.
- 모든 적은 돌파 시 보호막에 1피해를 준다.
- 보호막이 0 이하가 되면 블록 실패다.
- 보호막 회복은 현재 프로토타입에 구현하지 않았다.

### 4라운드 고정 흐름

```text
R1: 적 전진·전사·궁수 온보딩
→ 다음 라운드 예고
R2: 중장형 추가
→ 다음 라운드 예고
R3: 다중 전열 압박
→ 다음 라운드 예고
R4: 일반형·중장형 종합 검증
→ 결과 등급·재시작
```

- 네 라운드의 적 등장 순서와 열은 현재 고정이다.
- R1·R2·R3에서는 다음 라운드 예고 화면, R4에서는 결과 화면을 표시한다.
- 결과 화면에는 누적 사용량이 높은 주력 전술, 총 탭 수, 잔여 보호막, 근접·궁수·연계 사용 횟수를 표시한다.
- 등급은 `S: 보호막 3·24탭 이하`, `A: 보호막 2 이상`, `B: 보호막 1 이상`, `C: 그 외` 조건으로 계산한다.
- 실패 시 도달 라운드와 총 탭 수를 보여주고 처음부터 다시 시작한다.

### UI·피드백

- 모바일 세로 화면을 기준으로 라운드 트랙, 보호막, 남은 적, 전투선, 전사·궁수 버튼을 한 화면에 배치한다.
- 색상만으로 구분하지 않도록 `NORMAL ◆·ARMOR ●` 문구와 기호를 함께 사용한다.
- 적에는 유형, 체력, 캐릭터 공격 대상 아이콘을 표시한다.
- 캐릭터 버튼에는 공격 방식, 대상 수와 피해를 함께 표시한다.
- 마우스·키보드 포커스 시 해당 후보가 공격할 결정이 강조된다.
- 유효 공격에는 화면 플래시, 피해·처치 수·돌파 피해 문구를 제공한다.
- 시작 안내, 게임 방법, 능력 선택, 다음 라운드 예고, 성공 결과, 실패 결과를 모달 화면으로 구현했다.
- 캐릭터·결정·광원은 외부 리소스 없이 CSS 더미 그래픽으로 표현했다.

### 핵심 판단

> 가장 가까운 한 줄을 전사로 공격할 것인가, 아직 멀리 있는 중장형을 궁수로 먼저 제거할 것인가?

### 미구현 확장안

8라운드형은 현재 4라운드 블록을 두 번 연결하는 안이며 구현되지 않았다. 라운드 무작위화, 블록 사이 회복, 능력 6종 확장, 영구 성장과 경제 역시 현재 구현 범위가 아니다.

이 한 질문이 시스템·콘텐츠·밸런스를 관통해야 한다.

## 9. 가장 빠른 테스트 방식

현재 검증 대상은 외부 리소스 없이 제작한 로컬 HTML 프로토타입이다.

### 테스트 질문

1. 첫 행동에서 근접과 궁수 중 무엇을 선택했고 그 이유는 무엇인가
2. 즉시 제거량과 아래층 색 개방 중 무엇을 우선했는가
3. 판의 번호와 행동 후보의 공격 위치 관계를 설명 없이 이해했는가
4. 교대 공격이 연계 후보를 만든다는 사실을 인식했는가
5. 다시 플레이한다면 근접·궁수·연계 중 다른 능력을 선택하고 싶은가

### 최소 측정값

- 캐릭터별 첫 선택률
- 후보 번호와 공격 위치를 잘못 연결한 횟수
- 라운드별 평균 탭 수
- 라운드별 피격 횟수와 잔여 보호막
- 연계 공격 사용 횟수와 준비 후 미사용 횟수
- 능력별 선택률
- 4라운드 도달률과 완료 시간
- 규칙 오해 횟수
- 재플레이 의향 5점 척도

테스트 결과가 없으면 결과 수치를 만들지 말고 `테스트 계획`이라고 명시한다.

- Codex가 구현 편의를 위해 정한 수치·규칙은 `Codex 임의 구체화`로 표시한다.
- 프로토타입과 문서가 달라지면 같은 작업 안에서 문서를 함께 갱신한다.
- 테스트 전 수치는 검증값이 아니라 더미값으로 취급한다.
- 이후 개발은 헤더 왼쪽과 모달 오른쪽 위의 버전명을 함께 갱신하고, CSS·JavaScript 캐시 버전도 같은 값으로 맞춘다.
