# 1. 게임 개요

## 한 줄 소개

> 네 개의 룬을 직접 그려 적을 처치하고, 흔적으로 줄어드는 보드 공간까지 관리하는 모바일 퍼즐

## 핵심 경험

룬 경로를 직접 그리면 경로 위 몬스터가 처치됩니다. 완성한 룬은 흔적으로 남아 다음 룬의 배치 공간을 줄입니다. 현재의 공격이 미래 행동의 비용이 되는 구조입니다.

| 항목 | 내용 |
|---|---|
| 보드 | 7×7 |
| 입력 | 제시된 룬을 회전·반전해 직접 그리기 |
| 한 플로어 | 룬 최대 4회 |
| 한 스테이지 | 3개 플로어 |
| 한 챕터 | 3개 스테이지, 총 9개 플로어 |
| 성장 | 직접 처치 EXP와 능력 선택 |
| 보스 | 각 스테이지 마지막 플로어 |
| 실패 | 남은 룬 배치 불가 또는 보스 생존 |

# 2. 독창성과 차별점

## 직접 그리는 입력

룬을 버튼으로 배치하지 않습니다. 플레이어가 보드 위에 직접 경로를 그리며, 입력한 모양을 남은 룬과 자동으로 대조합니다. 첫 행동과 공격 결과가 같은 화면에서 이어집니다.

## 공격이 공간 자원을 소비

일반적인 체력 감소 대신 보드 공간을 실패 자원으로 사용합니다. 많은 적을 처치한 경로도 다음 룬을 막으면 나쁜 선택이 될 수 있습니다.

## 사전 정보 기반 판단

몬스터와 보스의 이동, 오염 예정, 처치 결과를 행동 전에 공개합니다. 무작위는 보드 상황을 바꾸지만 플레이어의 결정 뒤 결과를 숨기지 않습니다.

## 짧은 세션 안의 빌드

한 플로어의 행동을 최대 네 번으로 제한합니다. 직접 처치 EXP와 능력 선택을 통해 짧은 챕터 안에서도 플레이 방식이 달라집니다.

## 조합형 콘텐츠

룬·몬스터·이동·오염·능력·보스 변형을 조합합니다. 보드와 입력 시스템을 재사용하면서 서로 다른 판단을 만드는 것이 생산 원칙입니다.

# 4. 타깃과 시장 기회

## 핵심 타깃

> 복잡한 조작보다 간단한 퍼즐을 선호하고, 짧은 한 판에서도 성장과 플레이 변화를 느끼고 싶은 모바일 이용자

## 플레이 상황

- 통학·출퇴근 중 대기
- 학생의 쉬는 시간
- 취침 전 짧은 플레이
- 한 번에 한 스테이지
- 중단 후 같은 플로어부터 복귀

## 검증층과 상업층

| 구분 | 범위 | 확인 목적 |
|---|---|---|
| 초기 사용성 검증층 | 한국 16~24세 | 짧은 휴식 플레이와 조작 이해 |
| 상업 검증층 | 한국 20~44세 | 실제 퍼즐 수요와 유지·수익화 |
| 확장 검토층 | 아랍어권 18~34세 | RTL, 현지화, 광고·결제 반응 |

학생만을 상업 타깃으로 한정하지 않습니다. 초기 사용성은 짧은 휴식 이용자에게 확인하고 실제 상업 코호트는 유입 데이터로 다시 분류합니다.

## 시장 기회 가설

- 룬을 직접 그리는 조작이 일반 탭·매치 퍼즐과 다른 첫 인상을 만듭니다.
- 광고에서 보여준 행동을 실제 첫 플레이에서 그대로 수행할 수 있습니다.
- 퍼즐 수요는 크지만 경쟁도 높으므로 직접 입력과 공간 실패가 차별화 요소가 되어야 합니다.
- 능력 빌드와 보스가 단순 퍼즐의 반복 동기를 보완합니다.

시장 수치는 이 문서의 부록에 출처와 함께 분리합니다. 수요가 존재한다는 사실을 게임의 성공 가능성으로 바로 해석하지 않습니다.

# 5. 세션과 성장

## 세션 구조

| 단위 | 구성 | 목표 시간 | 역할 |
|---|---:|---:|---|
| 플로어 | 룬 최대 4회 | 1~3분 | 하나의 보드 문제 |
| 스테이지 | 3개 플로어 | 5~10분 | 성장 최소치와 보스 확인 |
| 챕터 | 3개 스테이지 | 15~30분 | 하나의 빌드 완성 |

- 플로어 클리어마다 진행 상태를 저장합니다.
- 레벨·EXP·능력은 플로어와 스테이지 사이에 유지합니다.
- 챕터 종료 시 레벨·EXP·능력을 초기화합니다.
- 아웃게임 재화와 외형은 제품화 단계에서 유지 대상으로 검토합니다.

## 능력 구조

> 능력은 수치만 높이지 않고 좋은 경로의 기준을 바꾼다.

| 능력 | 분류 | 핵심 변화 |
|---|---|---|
| 유혹 | 전투 | 이동 예정 칸을 룬으로 막아 충돌 |
| 도탄 | 전투 | 다수 직접 처치 후 가까운 대상 추가 공격 |
| 끝점 참격 | 전투 | 룬 끝점과 진행 방향을 공격 범위로 사용 |
| 오염 무시 | 퍼즐 | 오염 칸 1개 통과 |
| 룬 연결 | 퍼즐 | 이전 흔적 제거와 공간 재구성 |
| 룬 교체 | 퍼즐 | 남은 룬 형태 변경 |

전투 능력은 추가 처치로 공간을 확보하고 퍼즐 능력은 직접 경로와 EXP 획득을 안정화합니다. 순수 전투, 순수 퍼즐, 혼합 빌드를 허용합니다.

# 6. 보스와 난도 관문

## 역할

- 스테이지 1·2: 성장 최소치와 기본 기믹 이해 확인
- 스테이지 3: 완성된 빌드와 공간 판단 확인

## 이동형 보스

- 일반 몬스터보다 먼저 이동 칸을 예약합니다.
- 예약 방향은 행동 전에 공개합니다.
- 새 룬으로 예약 칸을 막으면 돌진 충돌 피해를 받습니다.
- 한 행동에서 최대 1회만 피해를 받습니다.
- 완전히 갇히면 주변 흔적·오염·일반 몬스터 중 하나를 제거하고 탈출합니다.

## 변형

| 스테이지 | 변형 | 공략 |
|---|---|---|
| 1 | 약점 표식 | 표식을 룬 경로가 직접 통과 |
| 2 | 수호 연결 | 연결된 일반 몬스터 처치 |
| 3 | 증원 소환 | 보스 피격 후 생존 시 일반 몬스터 소환 |

방어막, 필요 타격 수, 변형은 진입 시 먼저 공개합니다. 특정 능력이나 구매형 도구를 필수로 요구하지 않습니다.

# 8. 프로토타입 개선 근거

| 확인한 문제 | 판단 | 반영 |
|---|---|---|
| 항상 다수 타격이 유리함 | 현재 이득에 다음 행동 비용 필요 | 흔적과 공간 부족 실패 |
| 실시간 압박이 판단을 방해 | 생각할 시간 보장 | 턴제 이동과 방향 공개 |
| 오염이 계획을 무효화 | 공개 정보가 실제 전략으로 이어져야 함 | 오염 예정과 생성 상한 |
| 보스 타격 수단 부족 | 보드 규칙을 공략에 사용 | 돌진 충돌·약점·수호 |
| 보스가 갇혀 진행 차단 | 초기화에 의존하지 않는 예외 필요 | 탈출 이동 |

## 오염 긴급 조정

- 행동당 오염 대상 최대 2체
- 플로어당 몬스터 오염 최대 6칸
- 실제 이동한 몬스터만 오염 생성
- 취소된 오염을 같은 턴에 재배정하지 않음
- 보스는 오염 대상에서 제외

이 변경은 난도를 낮추기 위한 목적보다 예측 정보가 실제 전략으로 이어지게 하기 위한 조정입니다.

기존 시스템의 조합으로 업데이트 사이의 공백을 채우고, 신규 챕터에서는 새로운 규칙과 시각 테마를 제공합니다.

## 도구

도구는 귀찮음을 줄이거나 단발성 실패를 보완합니다.

| 도구 | 역할 |
|---|---|
| 탐색 렌즈 | 최대 처치 룬과 경로 정보 제공 |
| 교차 인장 | 다음 룬이 기존 흔적 1칸 통과 |
| 정화 도구 | 선택한 오염 칸 1개 제거 |

도구는 능력과 빌드를 대신하지 않으며, 도구 없이 해결할 수 없는 정상 보드를 만들지 않습니다.

## 수익화

- 보상형 광고: 런 종료 후 재화 추가, 능력 후보 교체, 도구 무료 획득
- 인앱 구매: 광고 제거, 도구 묶음, 보드·룬·UI·배경 외형
- 제외: 능력 영구 적용, 챕터 스킵, 룬 행동 횟수 판매

수익화는 코어 재미와 초기 유지가 확인된 뒤 검증합니다.

# 11. 제품화 계획

## 전제

현재 웹 프로토타입의 핵심 규칙을 유지한 채 6개월 이내 모바일 출시 후보 빌드를 목표로 합니다. 아트와 사운드는 외주 또는 프로젝트 단위 협업을 전제로 합니다.

| 기간 | 목표 결과물 | 진행 조건 |
|---|---|---|
| 1개월차 | 모바일 UI·터치 입력, Android 테스트 빌드 | 코어 규칙 유지 |
| 2개월차 | 튜토리얼·저장·로그 보완, 아트·사운드 착수 | 첫 행동·복귀 검수 |
| 3개월차 | 핵심 리소스 통합, 챕터 콘텐츠와 밸런스 | 모바일 입력 동일성 |
| 4개월차 | 외부 초행 테스트, 주요 기기 QA | 진행 차단 오류 해소 |
| 5개월차 | 출시 후보 빌드, 스토어·광고·분석 연동 | 데이터와 보상 검수 |
| 6개월차 | 최종 QA, 스토어 심사와 초기 마케팅 | 출시 기준 충족 |

## 단계별 의사결정

1. 코어 조작과 실패 이해가 확인되지 않으면 콘텐츠 확장을 중단합니다.
2. 목표 세션 시간과 초기 유지가 확인된 뒤 메타와 수익화를 추가합니다.
3. 광고 소재와 실제 플레이의 일치를 유지합니다.
4. 해결 불가능한 보드와 진행 차단을 자동 QA로 검사합니다.

# 12. 팀 구성과 상금 활용

## 구성

| 역할 | 인원 | 범위 |
|---|---:|---|
| 핵심 개발·기획 | 1명 | 개발, 시스템·콘텐츠·UX·밸런스, 통합 |
| 아트 협업 | 1명 | 캐릭터·보드·UI·연출 |
| 사운드 협업 | 1명 | 입력·공격·성공·실패 피드백 |

외부 테스트, 기기 QA, 마케팅은 필요한 시점에 전문 서비스 또는 단기 협업으로 집행합니다.

## 상금 활용 우선순위

1. 모바일 UI와 아트 리소스 제작
2. 외부 초행 사용자 테스트와 주요 기기 QA
3. 스토어 등록 자료와 광고 소재
4. 사운드 리소스
5. 번역·현지화와 초기 운영 준비

세부 비율은 실제 외주 견적과 지원금 집행 기준을 확인한 뒤 확정합니다.

## 담당과 AI 활용

- 핵심 규칙, 요구사항, 우선순위, 예외, 검수 기준은 직접 정의했습니다.
- AI는 HTML·CSS·JavaScript 구현과 반복 수정의 보조 도구로 사용했습니다.
- 생성 결과는 실제 프로토타입, 자동 QA, 플레이 로그로 검수했습니다.

- 인게임 스크린샷

- 요구 실행파일 형식
- 시연 영상 길이와 파일 형식
- 팀원·사업자 정보
- 개인정보와 AI 활용 고지

2026년 공개 안내 기준으로 플레이 가능한 미출시 게임이 대상이며, 세부 자격과 제출 형식은 공고문을 최종 기준으로 확인합니다.

# 결론

룬 트레이스는 단순히 적을 많이 처치하는 퍼즐이 아닙니다. 직접 그린 공격 경로가 다음 행동의 공간을 줄이기 때문에 현재 이득과 미래 선택을 함께 판단합니다.

현재 프로토타입은 코어 규칙, 능력 빌드, 이동형 보스, 저장·복원, 로그 수집까지 확인했습니다. 경기게임오디션을 통해 모바일 입력과 비주얼을 제품 수준으로 전환하고, 외부 사용자와 시장 지표로 다음 투자 여부를 판단하는 것이 목표입니다.
