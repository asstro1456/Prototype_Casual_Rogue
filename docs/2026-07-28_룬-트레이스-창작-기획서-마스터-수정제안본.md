# 2. 코어 플레이와 핵심 규칙

## 핵심 문장

> 한 번의 경로로 적을 베고, 공간을 만들며, 다음 성장을 설계한다.

룬은 몬스터를 처치하고 오염 압박을 줄일 수 있습니다. 동시에 완성한 경로는 흔적으로 남아 이후 룬의 배치 공간을 줄입니다. 한 번의 입력이 현재 전투와 다음 행동에 모두 영향을 주는 구조입니다.

## 코어 플레이 루프

룬 형태와 몬스터 이동·오염 예정 확인  
→ 적절한 위치 탐색  
→ 보드에 룬 직접 입력  
→ 직접 공격과 능력 효과 처리  
→ 몬스터 이동 및 오염 생성  
→ 다음 룬의 위치와 성장 방향 판단  
→ 클리어 또는 실패

## 한 행동에서 판단하는 요소

- 현재 몇 명의 적을 직접 처리할 수 있는가
- 다음 행동을 위한 빈 공간이 얼마나 남는가
- 이동 예정인 적을 막거나 능력 효과로 이용할 수 있는가
- 직접 처치 EXP를 확보할 수 있는가
- 보유 능력의 발동 조건을 만족할 수 있는가
- 보스의 다음 위치와 추가 기믹에 대응할 수 있는가

## 핵심 실패 규칙

> 완성한 룬은 흔적으로 남아 보드 공간을 차지하며, 다음 룬을 놓을 수 없으면 패배한다.

보편적인 HP 감소 대신 보드 공간을 실패 자원으로 사용합니다. 플레이어의 이전 선택과 몬스터의 오염이 다음 행동의 가능성을 줄입니다.

## 기본 규칙 — 구현 완료

- 보드는 7×7 칸으로 구성합니다.
- 각 플로어에는 네 개의 룬이 제시됩니다.
- 룬은 직각 회전과 좌우 반전을 허용합니다.
- 입력한 경로는 남은 룬과 자동으로 대조합니다.
- 룬 경로 위의 몬스터를 직접 공격합니다.
- 완성된 경로는 흔적으로 남습니다.
- 일부 몬스터는 이동한 뒤 이전 칸을 오염시킵니다.
- 흔적과 오염 칸에는 기본적으로 새 룬을 놓을 수 없습니다.
- 기존 룬 경로를 가로질러 통과할 수 없습니다.
- 잘못된 룬 입력은 행동으로 소비하지 않습니다.

## 클리어 조건

### 일반 플로어

- 룬 네 개를 모두 완성하거나
- 남은 룬을 모두 사용하기 전에 일반 몬스터를 전부 처치하면 클리어합니다.

### 보스 플로어

- 네 번째 룬 행동까지 보스를 처치하면 클리어합니다.
- 보스를 처치하면 남은 일반 몬스터와 관계없이 관문을 통과합니다.

## 실패 조건

- 남은 룬 중 어느 것도 현재 보드에 배치할 수 없으면 실패합니다.
- 네 번째 룬 처리 후 보스가 생존하면 보스전에서 실패합니다.

## 공정성 원칙

- 몬스터와 보스의 이동 방향은 행동 전에 공개합니다.
- 오염 예정 대상과 칸을 행동 전에 공개합니다.
- 입력 중에 무작위 이동 결과를 다시 설정하지 않습니다.
- 미리보기와 실제 처리 결과를 일치시킵니다.
- 강제 종료와 복귀로 무작위 결과를 다시 추첨할 수 없게 합니다.
- 실패 원인은 보드와 결과 화면에서 확인할 수 있어야 합니다.

# 3. 차별점과 핵심 경험

## 핵심 훅

> 목록에 제시된 룬을 직접 그려 적을 처치하는 간단한 구조

룬을 버튼으로 배치하는 대신 보드 위에 직접 그립니다. 입력한 경로는 공격과 동시에 흔적으로 남아 이후 룬의 배치 공간을 제한합니다.

## 차별점

### 직접 입력과 즉각적인 결과

룬을 직접 그리면 경로 위 몬스터가 바로 처치됩니다. 조작 방식과 결과를 첫 플레이와 광고에서 짧게 전달할 수 있습니다.

### 공격이 곧 공간 소모

많이 처치한다고 항상 좋은 것은 아닙니다. 많은 적을 처리한 경로가 이후 룬을 놓을 공간을 막을 수 있습니다. 플레이어는 처치와 공간 보존을 동시에 판단해야 합니다.

### 사전 정보 기반 판단

몬스터의 다음 이동 방향과 오염 예정 정보를 먼저 보여줍니다. 플레이어는 무작위 결과에 대응하는 것이 아니라, 공개된 결과를 이용해 경로를 선택합니다.

## 게임 필러

1. 직접 그리는 직관적인 조작
2. 한 수에 전투와 공간을 모두 고려
3. 짧은 세션 안에서 변화하는 능력 빌드

## 재미 구조

### 조작의 재미

손가락으로 그린 룬이 공격으로 이어지는 즉각적인 결과를 제공합니다.

### 발견의 재미

같은 룬도 위치와 방향에 따라 처치 수, 남은 공간, 몬스터 이동 결과가 달라집니다.

### 판단의 재미

전부 처치, 공간 보존, EXP 획득, 능력 발동 중 무엇을 우선할지 선택합니다.

### 성장의 재미

능력을 획득하면 이전에는 불가능했던 처치 방식과 경로 운용을 사용할 수 있습니다.

## 플레이 감정 흐름

보드와 룬 확인  
→ 가능한 경로 발견  
→ 더 좋은 위치 탐색  
→ 입력 확정  
→ 연속 처치 만족  
→ 몬스터 이동과 공간 감소  
→ 다음 룬에 대한 고민 증가  
→ 마지막 룬 성공 또는 공간 부족 실패

# 4. 장르 포지셔닝·타깃·시장 기회

## 기획 출발점

모바일 퍼즐은 조작이 단순하고 진입 장벽이 낮습니다. 반면 동일한 입력이 반복되면 플레이 변화가 약해질 수 있습니다. 로그라이크는 랜덤성과 빌드 조합으로 반복 동기를 제공하지만 한 판의 길이와 학습 피로가 커질 수 있습니다.

룬 트레이스는 두 장르의 장점을 결합하되 다음 원칙을 유지합니다.

- 조작은 한 손으로도 이해할 수 있어야 합니다.
- 한 플로어의 기본 행동 수는 4회로 제한합니다.
- 능력은 수치보다 경로와 공간의 판단을 바꿉니다.
- 체력 대신 보드 공간을 실패 자원으로 사용합니다.
- 한 스테이지는 짧은 휴식 시간 안에 끝낼 수 있어야 합니다.

## 핵심 타깃

> 복잡한 조작보다 간단히 풀 수 있는 퍼즐을 선호하거나, 한 판만으로 성장과 플레이 변화를 느끼고 싶은 모바일 유저

## 이용 성향

- 규칙을 오래 학습하기보다 플레이로 익히는 것을 선호합니다.
- 짧은 한 판에서도 선택의 결과가 분명한 게임을 선호합니다.
- 정답 하나를 찾기보다 여러 선택지를 비교하는 퍼즐을 선호합니다.
- 긴 런이나 복잡한 장비 관리에는 부담을 느낄 수 있습니다.
- 실패 원인이 명확하면 다른 방법으로 바로 재도전합니다.

## 주요 플레이 상황

- 통학·출퇴근 중 짧은 대기 시간
- 학생의 쉬는 시간
- 취침 전 짧은 플레이
- 한 번에 한 스테이지 진행
- 중단 후 같은 플로어부터 재개

## 유저 요구와 설계 대응

| 유저 요구 | 설계 대응 |
|---|---|
| 빠르고 간단하게 조작하고 싶음 | 직접 경로 입력, 최소 메뉴 |
| 짧아도 고민하고 싶음 | 룬 4회 안에서 공간·처치 비교 |
| 실패 이유를 알고 싶음 | 이동·오염 예고, 공간 부족 표시 |
| 반복할 이유가 필요함 | 능력 선택, 보스 변형, 룬 조합 |
| 중간에 나갈 수 있어야 함 | 플로어 단위 저장·복귀 |

## 시장 기회 가설

룬을 직접 그리는 조작은 일반적인 탭·매치 퍼즐과 다른 첫 인상을 만들 수 있습니다. 경로 입력, 연속 처치, 오염 확산, 공간 부족 실패가 모두 보드 안에서 표현되므로 광고와 실제 플레이의 행동을 맞추기 쉽습니다.

다음 가설을 실제 지표로 검증해야 합니다.

- 직접 그리는 조작이 광고의 후킹 요소가 되는가
- 첫 플레이에서 핵심 규칙을 빠르게 이해하는가
- 공간 관리가 불쾌한 제한이 아니라 판단의 재미로 인식되는가
- 능력 선택이 다음 플레이의 동기가 되는가
- 광고에서 본 행동과 실제 플레이의 일치가 초기 이탈을 줄이는가

## 시장 근거 정리 방식

본문에서는 시장 자료에서 도출한 방향만 설명합니다. 국가별 수치, 표본, 출처, 수익성 계산은 문서 맨 뒤의 `부록 C. 수치·시장 데이터`에 모아 정리합니다. 시장 사실과 룬 트레이스에 대한 해석도 같은 문장 안에서 섞지 않습니다.

## 서브컬처 캐주얼 분석 — 작성 예정

현재 프로토타입은 코어 퍼즐 검증에 집중합니다. 서브컬처 요소는 구현 완료 기능이 아니라 캐릭터, 테마, 수집 동기를 결합할 수 있는 확장 방향으로 구분합니다.

작성 시 다음을 확인합니다.

- 서브컬처 캐주얼에서 캐릭터가 플레이 동기와 수집 동기에 미치는 역할
- 퍼즐 규칙을 방해하지 않는 캐릭터 노출 방식
- 능력·룬·보스 기믹과 캐릭터 테마의 연결 가능성
- 외형 수집과 코어 성장의 분리

# 5. 첫 플레이·광고·튜토리얼·UX

## 설계 원칙

> 광고에서 본 행동을 첫 플레이에서도 바로 수행하게 한다.

광고 소재, 스토어 이미지, 첫 플레이의 조작이 다르면 설치 후 이탈 가능성이 커집니다. 첫 1분 안에 룬 확인, 직접 그리기, 적 처리, 흔적 생성을 경험하게 합니다.

## 광고 소재 가설

### 소재 A. 마지막 룬 공간 남기기

많은 적을 처리하는 경로를 먼저 보여준 뒤, 마지막 룬을 놓지 못해 실패합니다. 이후 공간을 남기는 경로로 성공합니다.

> 적을 많이 잡으면 오히려 실패합니다.

### 소재 B. 같은 룬, 다른 결과

같은 룬을 서로 다른 위치에 배치합니다. 처치 수, 남은 공간, 다음 이동 결과가 달라지는 모습을 비교합니다.

### 소재 C. 네 개의 룬 도전

처음부터 네 개의 룬과 보드를 함께 보여줍니다. 네 개를 모두 배치할 수 있는지 질문합니다.

## 튜토리얼 흐름 — 확장 계획

1. 첫 룬의 추천 위치를 반투명 경로로 보여줍니다.
2. 플레이어가 직접 경로를 완성합니다.
3. 경로 위 몬스터 처치와 흔적 생성을 보여줍니다.
4. 두 번째 룬에서 여러 배치 방법을 제시합니다.
5. 몬스터 이동과 오염을 경험시킵니다.
6. 마지막 룬에서 공간 관리 필요성을 체험시킵니다.

긴 텍스트보다 한 번의 플레이 안에서 규칙을 익히게 합니다.

## UX 정보 우선순위 — 확정 기획

1. 처치 예정
2. 몬스터와 보스의 이동 화살표
3. 오염 예정

정보가 겹치면 상위 정보를 먼저 읽을 수 있어야 합니다.

## 주요 표시 규칙

- 이동 화살표는 몬스터 내부가 아니라 현재 칸과 목적지 칸 사이에 표시합니다.
- 처치 예정 대상은 알파값을 낮춰 표시합니다.
- 보스의 방어막, 필요 타격 수, 변형 효과는 진입 시 먼저 공개합니다.
- 능력은 평소 아이콘으로 유지하고 클릭 또는 호버로 상세 설명을 엽니다.
- 레벨업 선택은 가장 높은 우선순위의 모달로 표시합니다.
- 모달을 감춘 뒤 화면을 클릭하면 능력 선택을 다시 확인할 수 있어야 합니다.
- QA 패널은 보드를 가리지 않는 게임 화면 밖에 배치합니다.

## 텍스트 가독성 기준

- 플레이에 필요한 정보는 보조 문구보다 크게 표시합니다.
- 제목과 핵심 수치는 본문보다 굵게 표시합니다.
- 발동 조건, 핵심 수치, 상태 변화만 선택적으로 강조합니다.
- 플레이 화면의 핵심 설명은 짧은 문장으로 제한합니다.
- 중요한 상태를 색상만으로 구분하지 않습니다.

구체적인 글자 크기와 문장 길이는 부록의 초기 UI 기준에서 관리합니다.

## 튜토리얼·UX 확인 지표

- 첫 행동까지 걸린 시간
- 첫 룬 입력 성공률
- 잘못된 경로 입력 횟수
- 첫 플로어 진입률
- 첫 플로어 클리어율
- 튜토리얼 중 이탈률
- 이동·오염 예고 이해도

첫 플레이에서 핵심 규칙을 이해한 뒤에는 능력 선택과 보스 관문이 반복 동기를 이어받습니다.

# 6. 세션·성장·반복 구조

## 세션 구조

| 단위 | 구성 | 역할 |
|---|---:|---|
| 플로어 | 룬 최대 4회 | 짧은 단위의 문제 상황 |
| 스테이지 | 3개 플로어 | 성장 최소치와 판단 숙련 확인 |
| 챕터 | 3개 스테이지 | 하나의 빌드 완성 |

현재 시간값은 실측이 아닌 목표값입니다.

- 플로어: 약 1~3분
- 스테이지: 약 5~10분
- 챕터: 약 15~30분

세션 목표와 판정 기준은 `부록 C. 수치·시장 데이터`에서 한 번에 관리합니다.

## 챕터 내부 성장 루프

플로어 진입  
→ 직접 처치 EXP 획득  
→ 레벨업 능력 선택  
→ 스테이지 보스 공략  
→ 다음 스테이지 진입  
→ 챕터 보스 공략  
→ 능력·레벨·EXP 초기화

## 성장 구조 — 구현 완료

- 직접 경로로 일반 몬스터를 처치하면 EXP 1을 획득합니다.
- 전투 능력으로 추가 처치한 몬스터는 EXP를 지급하지 않습니다.
- 레벨업 요구치는 챕터 안에서 증가하지 않습니다.
- 레벨업 시 능력 카드 최대 3장을 제시합니다.
- 최대 단계에 도달한 능력은 후보에서 제외합니다.
- 선택한 능력은 해당 챕터 동안 유지됩니다.

현재 EXP 요구치와 목표 능력 선택 횟수는 초기 밸런스값이므로 부록에서 관리합니다.

## 아웃게임 루프 — 확장 계획

플로어 전멸 또는 챕터 완료  
→ 아웃게임 재화 획득  
→ 도구 확보 또는 외형 상품 해금  
→ 새로운 챕터 도전

- 능력과 레벨은 챕터 단위로 초기화합니다.
- 아웃게임 재화와 획득한 외형은 유지합니다.
- 범용 인게임 특수 자원은 도입하지 않습니다.
- 재화 지급량, 도구 가격, 무료 공급량은 미정입니다.
- 외형 해금용 플레이 재화와 유료 외형 상품은 구분합니다.

## 반복 동기

- 룬 조합과 순서 변화
- 몬스터 배치와 이동 방향 변화
- 능력 선택지 변화
- 보스 변형과 일반 몬스터 구성 변화
- 실패 후 다른 경로 시도

### 확장 계획

- 능력 또는 룬 도감
- 도전 과제
- 챕터별 최고 기록
- 테마와 외형 수집
- 일일·주간 도전
- 시즌별 도전 진행도

메타 시스템이 핵심 퍼즐보다 앞서지 않게 합니다.

# 7. 능력·빌드·전략 다양성

## 설계 목표

> 능력은 수치 상승에 그치지 않고, 경로 선택과 공간 운용 방식을 바꾼다.

능력은 전투와 퍼즐 두 갈래로 구성합니다. 두 계열은 같은 룬 배치 안에서 서로 보완합니다.

- 전투 능력은 추가 처치와 공간 확보를 돕습니다.
- 퍼즐 능력은 직접 경로와 배치 가능성을 안정화합니다.
- 순수 전투, 순수 퍼즐, 혼합 빌드를 모두 허용합니다.
- 능력으로 발생한 처치는 다른 능력을 연쇄 발동시키지 않습니다.
- 같은 대상은 한 번의 룬 행동에서 최대 1회만 피격됩니다.

## 능력 구성 — 구현 완료

| 능력 | 분류 | 최대 단계 | 핵심 효과 |
|---|---|---:|---|
| 유혹 | 전투 | 3 | 새 룬에 이동이 막힌 일반 몬스터를 룬으로 충돌시킴 |
| 도탄 | 전투 | 3 | 일반 몬스터 2체 이상 직접 처치 시 가까운 대상을 추가 공격 |
| 끝점 참격 | 전투 | 3 | 룬의 마지막 진행 방향과 끝점 주변을 추가 공격 |
| 오염 무시 | 퍼즐 | 1 | 플로어당 한 번 오염 칸 1개를 통과 |
| 룬 연결 | 퍼즐 | 1 | 기존 룬 끝점에서 새 룬을 잇고 이전 흔적을 제거 |
| 룬 교체 | 퍼즐 | 1 | 플로어당 한 번 남은 룬 하나를 다른 기본 형태로 교체 |

## 빌드 방향 예시

### 공격 확장 빌드

한 번의 룬으로 여러 몬스터를 처리하고 추가 공격을 이어갑니다.

- 도탄
- 끝점 참격
- 몬스터 밀집 구간 우선

### 이동 예측·충돌 빌드

몬스터의 이동 예정 칸을 룬으로 막아 추가 효과를 만듭니다.

- 유혹
- 이동 화살표 우선 확인
- 직접 공격 이후 생존 대상의 이동 경로 활용

### 공간·경로 유연성 빌드

오염과 흔적의 제약을 완화해 후반 룬 배치를 안정시킵니다.

- 오염 무시
- 룬 연결
- 룬 교체

## 다양성 확인 기준

- 능력에 따라 좋은 경로의 기준이 바뀌는가
- 서로 다른 능력이 같은 결과만 만들지는 않는가
- 특정 능력 없이도 보스를 공략할 수 있는가
- 능력 조합이 플레이어의 판단을 무의미하게 만들지는 않는가
- 한 가지 조합만 반복해서 선택하지는 않는가
- 선택 결과를 다음 플로어에서 바로 체감하는가

능력으로 만든 빌드는 각 스테이지의 보스에서 실제 공략 수단으로 확인됩니다. 보스는 성장의 이유를 만들되 특정 능력을 강제하지 않아야 합니다.

# 8. 보스 시스템

## 보스의 역할

> 보스는 현재 빌드가 필요한 성장 최소치를 채웠는지 확인하는 관문이다.

각 스테이지 마지막 플로어에 보스를 배치합니다. 스테이지 1·2는 비교적 가벼운 관문이며, 스테이지 3의 챕터 보스는 완성된 빌드와 퍼즐 판단을 확인합니다.

## 기본 이동형 보스 — 구현 완료

- 스테이지 1·2 보스는 비교적 적은 타격으로 처치할 수 있습니다.
- 스테이지 3 보스는 더 많은 타격을 요구합니다.
- 모든 몬스터의 본체는 방어막이 없을 때 1회 피격으로 처치됩니다.
- 보스는 일반 몬스터보다 먼저 다음 이동 칸을 예약합니다.
- 예약 이동 방향은 행동 전에 공개합니다.
- 한 번의 룬 행동에서 보스는 최대 1회만 피해를 받습니다.
- 네 번째 룬까지 보스를 처치하지 못하면 실패합니다.

스테이지별 방어막과 동반 몬스터 수는 부록의 초기 밸런스값을 따릅니다.

## 기본 기믹

### 돌진 충돌

플레이어가 새 룬으로 보스의 예약 이동 칸을 막으면 보스가 룬에 충돌합니다. 해당 행동에서 아직 피해를 받지 않았다면 피해 1회를 받고 현재 칸에 정지합니다.

### 탈출 이동

보스가 완전히 갇히면 정상 플레이의 층 초기화에 의존하지 않습니다. 주변의 룬 흔적, 오염, 일반 몬스터 중 하나를 제거하고 이동합니다. 탈출 자체는 보스에게 피해를 주지 않습니다.

## 보스 변형 — 구현 완료·검증 필요

| 스테이지 | 변형 | 핵심 효과 |
|---|---|---|
| 스테이지 1 | 약점 표식 | 표식을 룬 경로가 직접 통과하면 보스 피격 |
| 스테이지 2 | 수호 연결 | 연결된 일반 몬스터를 처치하면 보스 피격 |
| 스테이지 3 | 증원 소환 | 보스가 피격 후 생존하면 일반 몬스터 1체 소환 |

현재는 각 변형을 독립적으로 확인하기 위해 스테이지별로 고정합니다. 무작위 조합은 각 효과의 이해도와 난도를 검증한 뒤 재검토합니다.

## 공정성 원칙

- 스테이지 진입 시 방어막, 필요 타격 수, 변형 효과를 공개합니다.
- 현재 룬과 빌드로 해결할 수 없는 조합을 만들지 않습니다.
- 특정 능력이나 구매형 도구를 필수로 요구하지 않습니다.
- 보스의 이동, 약점, 연결, 소환 위치는 행동 전에 표시합니다.
- 같은 상태에서 결과를 다시 추첨할 수 없게 합니다.
- 보스가 영구적으로 갇히는 상황을 허용하지 않습니다.

## 확인할 지표

- 보스별 첫 시도 클리어율
- 변형별 클리어율·포기율·재시도율
- 보스 피격 출처
- 네 번째 룬까지 필요한 평균 타격 수
- 보스 기믹 미리보기 이해도
- 탈출 이동 발생 빈도

# 9. 도구와 아웃게임 구조

## 도구 설계 원칙 — 확정 기획

- 기본 게임에 의도적인 불편을 만든 뒤 해결책을 판매하지 않습니다.
- 정상적인 퍼즐은 도구 없이도 해결할 수 있어야 합니다.
- 도구는 귀찮음을 줄이거나 단발성 실패를 보완합니다.
- 도구는 능력과 빌드를 대신하지 않습니다.
- 도구는 세 종류만 유지합니다.

## 능력과 도구의 차이

| 구분 | 능력 | 도구 |
|---|---|---|
| 유지 | 챕터 동안 유지 | 사용 시 소모 |
| 효과 | 제한적이지만 반복 사용 | 단발성이지만 강력 |
| 역할 | 빌드와 플레이 방식 변화 | 탐색 피로와 단발성 실패 보완 |
| 획득 | 챕터 내부 레벨업 | 무료 공급·재화·상품 가설 |

## 탐색 렌즈

현재 턴에서 가장 많은 몬스터를 처리할 수 있는 룬을 보여줍니다. 후보 룬을 선택하면 최대 처리 경로를 보드 위에 표시합니다.

- 동률인 룬과 경로를 함께 표시합니다.
- 룬 하나당 경로는 최대 3개만 표시합니다.
- 최대 처치 수가 0이면 합법적인 경로를 표시합니다.
- 보스도 유효 목표 계산에 포함합니다.
- 표시한 경로를 정상 완성했을 때 도구와 턴을 소비합니다.

## 교차 인장

- 다음 룬 하나가 기존 룬 흔적의 칸 1개를 통과할 수 있습니다.
- 기존 흔적을 여러 칸 따라갈 수 없습니다.
- 오염과 보스 전용 장애물은 통과하지 않습니다.
- 실제로 교차한 룬을 완성했을 때 소비합니다.

## 정화 도구

- 선택한 오염 칸 1개를 즉시 제거합니다.
- 몬스터, 보스, 룬 흔적에는 사용할 수 없습니다.

## 검토 필요

- 챕터 반입 수량
- 같은 도구의 중복 반입 제한
- 도구 가격과 무료 공급량
- 사용한 도구와 재시작의 환불 규칙
- 유료 도구 없이 해결할 수 없는 보드의 발생 여부

도구는 콘텐츠 수를 늘리는 장치가 아닙니다. 반복 플레이의 변화는 룬, 몬스터, 보스, 특수 규칙의 조합에서 만듭니다.

# 10. 콘텐츠 생산과 업데이트 구조

## 생산 원칙

> 신규 콘텐츠는 수량만 늘리지 않고, 기존 시스템을 다르게 해석하게 만들어야 한다.

## 콘텐츠 조합 구조

룬 세트  
× 몬스터 구성  
× 보드 조건  
× 능력 풀  
× 보스 변형  
× 특수 규칙

각 요소를 조합해 보드와 입력 시스템을 재사용합니다. 조합 수만 늘리지 않고 해결 가능성과 정보 가독성을 함께 검증합니다.

## 확장 제약

- 보드는 모바일 가독성을 유지하는 범위에서 최대 9×9까지 검토합니다.
- 일반 룬은 4~6칸, 특수 룬은 최대 7칸을 상한으로 둡니다.
- 8칸 룬은 기본 확장 범위에서 제외합니다.
- 보드 확대보다 몬스터, 보스, 특수 칸의 판단 밀도를 먼저 조정합니다.

대형 룬의 보드 점유율 계산은 부록에 정리합니다.

## 확장 축

| 확장 요소 | 예시 | 변화하는 판단 |
|---|---|---|
| 룬 | 신규 룬, 제약 룬 | 배치 가능 위치 |
| 몬스터 | 방어, 이동, 연결 | 처치 우선순위 |
| 보드 | 장애물, 특수 칸 | 공간 활용 방식 |
| 능력 | 공격·경로·이동 제어 | 빌드 방향 |
| 보스 | 약점, 수호, 소환 | 공략 목표 |
| 목표 | 행동 제약, 처치 조건, 점수 | 플로어 평가 기준 |

## 업데이트 규모 — 확장 계획

### 저비용

- 일일 도전
- 고정 룬 세트
- 특정 능력 제한
- 오염 상한 안에서 생성 조건 변경
- 점수 경쟁
- 기존 콘텐츠 조합 변경

### 중간 규모

- 신규 룬
- 신규 능력
- 신규 몬스터 기본형
- 신규 보스 변형
- 특수 보드 규칙

### 대규모

- 신규 챕터
- 배경·연출 테마
- 신규 보스 기본형
- 시즌 진행 구조
- 신규 메타 시스템

제작 비용이 적은 조합형 콘텐츠로 업데이트 간 공백을 채웁니다. 중·대규모 업데이트에서는 새로운 규칙과 시각적 변화를 제공합니다.

# 11. 수익화와 운영 가설

## 기본 원칙

- 콘텐츠 진행도를 결제로 판매하지 않습니다.
- 실패 직후 광고를 반복해서 노출하지 않습니다.
- 광고 시청 여부가 기본 난이도를 결정하지 않게 합니다.
- 보상은 선택적으로 제안합니다.
- 도구 구매를 유도하기 위해 의도적인 불편을 만들지 않습니다.
- 유료 도구 없이 해결할 수 없는 정상 보드는 허용하지 않습니다.

## 보상형 광고 가설

- 런 종료 후 아웃게임 재화 추가 획득
- 능력 후보 1회 교체
- 도구 무료 획득
- 보상 증폭 선택권
- 일일 도전 추가 입장

실패 직전 부활은 우선순위를 낮춥니다. 공간 관리 실패를 광고로 즉시 지우면 핵심 퍼즐의 의미가 약해질 수 있습니다.

## 인앱 구매 가설

- 광고 제거 상품
- 탐색 렌즈·교차 인장·정화 도구 묶음
- 스타터 패키지
- 보드 테마
- 룬 선·이펙트 외형
- UI 외형
- 챕터 배경 테마
- 시즌 패스

룬 배치 횟수 추가, 능력 영구 적용, 챕터 스킵처럼 핵심 판단을 직접 제거하는 상품은 제외합니다. 룬 외형은 실루엣과 경로 인식을 방해하지 않아야 합니다.

## 운영 가설

- 일일 던전
- 특수 규칙이 적용된 주간 던전
- 특정 능력 체험 이벤트
- 시즌 챕터와 외형 보상
- 실패 원인과 능력 지표를 고려한 밸런스 조정

## 운영 확인 기준

- 보상형 광고의 제안 시점이 자연스러운가
- 광고 보상이 핵심 경험을 훼손하지 않는가
- 도구 사용이 정상적인 해결 과정을 대체하지 않는가
- 외형 테마가 구매 동기로 작동하는가
- 콘텐츠 업데이트 주기가 제작비 대비 유지 가능한가
- 결제 제안 이후 이탈과 불공정 인식이 증가하지 않는가

수익화와 운영은 코어 재미가 확인된 이후의 가설입니다. 현재 단계에서는 어떤 판단을 거쳐 프로토타입이 바뀌었는지가 우선입니다.

# 12. 프로토타입 변천과 개선 근거

## 개선 원칙

> 초기 아이디어를 유지하는 것보다 유저가 실제로 판단할 수 있는 재미를 남긴다.

## 프로토타입 수정 흐름

| 단계 | 확인한 문제 | 판단 | 반영한 요소 |
|---|---|---|---|
| 인접 블록 제거형 퍼즐 | 항상 다수를 타격하는 것이 유리해 전략이 고정됨 | 많이 처치하는 선택에도 다음 행동의 비용이 필요 | 룬 흔적 유지와 공간 부족 실패 |
| 실시간 디펜스 | 실시간 압박이 경로 판단을 방해함 | 생각할 시간을 보장해야 함 | 턴제 이동과 이동 방향 사전 공개 |
| 룬 트레이스 초기형 | 적의 움직임은 보이지만 오염이 계획을 무효화함 | 예측 정보가 실제 전략으로 이어져야 함 | 오염 대상 공개와 플로어 상한 |
| 이동형 보스 | 반복 타격 수단이 적고 보스가 갇힐 수 있음 | 공간 퍼즐을 이용하되 막힘 상태는 제거해야 함 | 돌진 충돌과 탈출 이동 |

## 대표 개선 사례 1. 오염 칸 수 과다

### 문제

몬스터의 동선은 예측할 수 있었지만 오염 칸이 빠르게 늘었습니다. 플레이어가 다음 수를 계획해도 배치 불가 칸이 지나치게 많이 생겼습니다.

### 수정

- 행동당 오염 대상 수 제한
- 플로어당 몬스터 오염 칸 수 상한
- 오염 대상과 예정 칸 사전 표시
- 실제로 이동한 몬스터만 이전 칸 오염
- 오염이 취소되어도 같은 턴에 다른 몬스터로 역할을 재배정하지 않음
- 보스는 오염 대상에서 제외

### 확인할 결과

- 이동 예고를 보고 세운 계획이 실제 결과와 이어지는가
- 공간 부족 실패가 갑작스럽지 않은가
- 오염 상한이 긴장감을 지나치게 낮추지는 않는가

## 대표 개선 사례 2. 몬스터 이동 화살표

### 문제

화살표를 몬스터 내부에 넣으면 적의 상태와 이동 정보가 겹쳤습니다.

### 수정

현재 칸과 이동할 칸 사이에 화살표를 배치했습니다. 방향 정보와 몬스터 상태를 분리했습니다.

## 대표 개선 사례 3. 보스 타격과 갇힘

### 문제

일반 몬스터는 남아도 클리어에 직접 영향을 주지 않았습니다. 반면 보스는 네 번의 룬 안에서 여러 번 공격해야 했고 타격 수단이 제한적이었습니다. 보스가 흔적과 오염에 갇히면 정상 진행도 막혔습니다.

### 수정

- 예약 이동 칸을 새 룬으로 막는 돌진 충돌 추가
- 한 행동 최대 1피격 유지
- 완전히 갇힌 보스의 탈출 이동 추가
- 약점 표식과 수호 연결로 직접 경로 외 타격 수단 제공

# 13. 검증 계획과 데이터

## 검증 원칙

시장성과 재미가 확인된 상태라고 단정하지 않습니다. 코어 조작, 공간 판단, 성장 동기, 상업성 순서로 검증합니다.

## 1단계. 코어 조작

- 첫 행동까지 걸린 시간
- 첫 룬 입력 성공률
- 잘못된 입력 횟수
- 회전·반전 형태 입력 성공률
- 드래그 조작 만족도
- 미리보기와 실제 결과의 불일치

## 2단계. 게임 구조

- 플로어 첫 시도 클리어율
- 세션 내 최종 클리어율
- 공간 부족 실패 비중
- 보스 생존 실패 비중
- 실패 후 단기 재시도율
- 실패 직후 이탈률
- 능력 선택 분포
- 능력별 직접·추가 처치 차이
- 스테이지 플레이 시간 분포
- 중단 후 복원 성공률

## 3단계. 초기 유지

- 첫 플로어 진입률
- 첫 스테이지 완료율
- 최초 세션 조기 이탈률
- D1·D7 잔존율
- 일일 세션 수
- 챕터 중단 후 복귀율

## 4단계. 상업성

- 광고 소재별 클릭률
- 설치 전환 효율
- 설치당 비용
- 광고비 회수율
- 보상형 광고 선택률·완료율
- 광고 노출 후 이탈률
- 도구 사용 가능 상황 대비 사용률
- 도구 사용 후 같은 시도 클리어율
- 결제 노출 후 이탈·환불·불공정 응답

상업 지표는 코어 조작과 초기 유지가 확인된 뒤 판단합니다.

## 추가 데이터 수집 계획

- 직접 플레이
- 입력 실패와 예외 사례 조사
- 자동 플레이 로그
- QA 패널과 자동 QA 지원 API
- 외부 플레이테스트 관찰
- 테스트 후 인터뷰

## 현재 로그 범위 — 구현 완료

- 세션 시작·종료·복귀
- 스테이지와 플로어 진입·종료
- 룬 선택과 경로 결과
- 직접·능력 처치
- 보스 진입·변형·피격·종료
- 실패 원인
- 능력 선택
- 저장 복원

## 초기 외부 플레이테스트 결과 — v1.0.0

본인·QA 반복 기록을 제외하고 외부 초행 사용자 3명의 자동 로그를 초기 사용성 자료로 분리했습니다. 표본이 작으므로 재미와 시장성을 확정하는 성과 지표가 아니라 조작 이해도, 진행 가능성, 재시도 흐름을 확인하는 근거로만 사용합니다.

| 항목 | 초기 결과 | 해석 범위 |
|---|---:|---|
| 외부 초행 사용자 | 3명 | 방향 확인용 소규모 표본 |
| 첫 플로어 클리어 | 3명 · 100% | 초행 사용자가 첫 플로어를 완료했는지 판단 |
| 챕터 완료 | 2명 · 66.7% | 완주자 2명, 나머지 1명은 스테이지 3 플로어 8까지 진입 |
| 플로어 종료 판정 | 36회 | 최종 v1.0.0 기록만 사용 |
| 플로어 클리어 | 35회 · 97.2% | 난도 확정값이 아니라 진행 가능성 확인 |
| 플로어 실패 | 1회 · 2.8% | 종료 판정에서 `success: false`로 기록된 시도 |
| 재시도 상태로 시작한 완료 시도 | 4회 | 실패 여부와 별개인 재시도 표식이며, 4회 모두 클리어 |
| 플로어 경과 시간 | 평균 약 37초 · 중앙값 약 31초 | 진행 중 모달·대기를 포함하며 목표 1~3분보다 짧음 |
| 챕터 완주자 활동 시간 | 약 7.2분 · 14.3분 | 목표 15~30분보다 짧은 사례가 있어 추가 초행 테스트 필요 |

### 데이터 해석 주의

- 참가자 4명·세션 16회의 전체 대시보드에는 본인 또는 QA로 보이는 반복 실행과 여러 버전이 섞여 있어 외부 테스트 성과로 사용하지 않습니다.
- `page_hide`와 재실행을 중간 이탈로 집계한 91.7% 값은 실제 플레이 포기율로 해석하지 않습니다.
- 경로 시도·유효 경로·무효 경로 집계는 입력 과정과 최종 룬 확정의 관계를 다시 확인한 뒤 입력 성공률로 사용합니다.
- 재시도 표식은 실패 횟수가 아닙니다. 자발적 층 초기화, 클리어 후 같은 층 재도전, 스테이지·챕터 재도전을 포함합니다.
- 플로어 경과 시간은 플로어 시작부터 종료 판정까지 측정하며 진행 중 모달과 대기를 포함합니다. 종료 판정 뒤 결과 모달은 제외하고, 현재 구현에서는 탭 비활성 시간도 포함될 수 있습니다.
- 이후 외부 초행 사용자 5~10명을 추가해 첫 행동 시간, 입력 실패 이유, 스테이지 시간, 실패 후 재시도를 다시 측정합니다.
- 정량 로그와 별도로 재미, 실패 이해도, 조작 불편, 재플레이 의향을 짧은 인터뷰로 확인합니다.

# 14. 현재 제작 범위와 담당 역할

## 구현 완료

- 7×7 경로 입력 보드
- 룬 기본형 6종과 자동 인식
- 회전·반전 처리
- 흔적과 오염 시스템
- 일반 몬스터 기본형 1종
- 이동형 보스 기본형 1종
- 보스 변형 3종
- 1챕터 · 3스테이지 · 9플로어
- 능력 6종
- 저장·복원
- 플레이 로그
- QA 패널
- 자동 QA 지원 API

## 프로토타입에서 제외한 범위

- Android 실행 파일
- 실제 모바일 비율 UI
- 완성 아트와 애니메이션
- 사운드·진동
- 정식 튜토리얼
- 도구와 아웃게임 경제
- 결제와 광고 연동
- 장기 메타 시스템
- 실제 라이브 운영

사운드는 현재 포트폴리오 제작 범위에서 제외합니다. 효과음 폴리싱보다 코어 규칙, 플레이테스트 정리, 문서 전달력을 우선합니다.

## 담당 역할

- HTML·CSS·JavaScript 기반 웹 프로토타입 개발
- 게임 콘셉트 및 핵심 규칙 설계
- 코어 루프와 세션 구조 설계
- 룬·몬스터·보스·능력 기획
- UI 기획과 UX 정보 우선순위 설계
- 시스템·콘텐츠 기획
- 오염·보스 구조의 초기 밸런스 조정
- 능력·보스·세션의 밸런스 기획
- 예외 처리 사례 정의
- 테스트 케이스 작성
- 플레이 로그 구조와 수집 환경 설계
- 프로토타입 검수·수정·통합

## 모바일 제품화 협업 구조

| 역할 | 인원 | 담당 범위 |
|---|---:|---|
| 핵심 개발·기획 | 1명 | 개발, UI·시스템·콘텐츠·밸런스 기획, 통합과 의사결정 |
| 아트 | 1명 | 캐릭터·보드·UI 리소스, 연출용 비주얼 제작 |
| 사운드 | 1명 | 효과음, 배경음, 입력·성공·실패 피드백 제작 |

아트와 사운드는 모바일 제품화 단계에서 외주 또는 프로젝트 단위 협업으로 확보합니다. 별도의 상시 개발 인력 증원을 전제로 하지 않으며, 외부 테스트와 마케팅은 필요한 시점에 전문 서비스 또는 단기 협업으로 집행합니다.

## AI 활용 범위

AI를 HTML·CSS·JavaScript 구현과 반복 수정의 보조 도구로 활용했습니다. 게임 규칙, 요구사항, 구현 우선순위, 예외 조건, 검수 기준을 직접 정의했습니다. 생성 결과는 실제 프로토타입에서 확인하고 수정 방향을 결정했습니다.

포트폴리오에서는 다음 흐름을 함께 보여줍니다.

기획 문제 발견  
→ 구현 요구사항 작성  
→ AI 보조 구현  
→ 플레이·로그·QA 검수  
→ 규칙 또는 UI 수정  
→ 변경 근거 기록

# 15. 조건부 제품화 로드맵

## 전제

현재 웹 프로토타입은 1인이 핵심 개발과 기획을 담당해 코어 조작과 시장 가능성을 검증한 결과물입니다. 경기게임오디션 선정 후에는 아트 1명과 사운드 1명을 외주 또는 프로젝트 단위 협업으로 확보하고, 6개월 이내 모바일 출시를 목표로 합니다. 빠른 출시를 우선하되 조작 안정성, 저장·복원, 핵심 로그, 스토어 심사에 필요한 품질 기준은 생략하지 않습니다.

| 기간 | 목표 결과물 | 진행 조건 |
|---|---|---|
| 1개월차 | 모바일 UI·터치 입력 전환, Android 테스트 빌드, 아트·사운드 작업 범위 확정 | 웹 프로토타입의 핵심 규칙 유지 |
| 2개월차 | 튜토리얼·저장·로그 보완, 아트·사운드 제작 착수, 1차 모바일 내부 테스트 | 첫 행동·첫 실패·복귀 흐름 검수 |
| 3개월차 | 핵심 아트·사운드 통합, 챕터 콘텐츠와 밸런스 조정 | 모바일 입력과 핵심 퍼즐의 동일성 확인 |
| 4개월차 | 외부 초행 사용자 테스트, 주요 기기 QA, 크래시·진행 불가 수정 | 클리어·실패·재시도·세션 시간 확보 |
| 5개월차 | 출시 후보 빌드, 스토어 자료, 광고·분석 연동, 마케팅 소재 준비 | 데이터 수집과 보상 구조 검수 |
| 6개월차 | 최종 QA, 스토어 심사, 출시와 초기 마케팅 | 진행 차단 오류 해소 및 출시 기준 통과 |

## 상금 활용 방향

- 아트와 사운드 리소스 외주 또는 프로젝트 단위 협업비
- 외부 초행 사용자 플레이테스트와 주요 모바일 기기 QA
- 스토어 등록 자료, 광고 소재, 출시 초기 마케팅
- 출시 과정에서 필요한 번역·현지화·운영 준비

세부 비율과 금액은 실제 외주 견적, 지원금 집행 기준, 출시 플랫폼 범위를 확인한 뒤 확정합니다. 메타게임과 장기 운영 구조는 코어 검증 이후에 확장합니다.

# 17. 결론

> 룬 트레이스는 직접 그리는 입력이 전투와 공간 관리에 동시에 적용되고,  
> 룬·몬스터·능력·보스 규칙의 조합으로 반복 가능한 콘텐츠를 만드는  
> 모바일 하이브리드 캐주얼 퍼즐 로그라이크입니다.

현재 프로토타입은 완성된 사업성을 주장하기 위한 결과물이 아닙니다. 직접 그리는 조작, 흔적으로 인한 공간 관리, 짧은 챕터 안의 능력 성장이 실제 플레이의 재미와 시장 지표로 이어질 가능성을 확인하기 위한 결과물입니다.

프로젝트의 핵심 성과는 아이디어의 수가 아닙니다. 플레이 중 불쾌하거나 막히는 지점을 규칙, 정보 표시, 예외 처리로 수정하고 다시 검증할 수 있는 구조를 만든 것입니다.

| 스테이지 3 보스 필요 타격 | 3회 | 초기 테스트값 |
| 스테이지 1·2 보스 동반 일반 몬스터 | 3체 | 초기 테스트값 |
| 스테이지 3 보스 동반 일반 몬스터 | 5체 | 초기 테스트값 |

적 수와 직접 처치율이 확정되지 않았으므로 EXP와 보스 수치는 플레이테스트 이후 조정합니다.

## C-3. 세션과 UI 목표값

| 항목 | 목표 |
|---|---:|
| 플로어 | 약 1~3분 |
| 스테이지 | 약 5~10분 |
| 챕터 | 약 15~30분 |
| 스테이지 활동 시간 중앙 구간 | P50 5~7분 |
| 스테이지 활동 시간 상위 구간 | P90 10분 이내 |
| 플레이 필수 정보 | 12px 미만 사용 금지 |
| 플레이 화면 핵심 설명 | 1문장·최대 2줄 |

세션 시간은 외부 시장 평균을 그대로 복사한 값이 아닙니다. 학생의 쉬는 시간과 모바일의 짧은 플레이 상황을 가정한 내부 목표입니다. 실제 판단은 평균보다 P50과 P90을 함께 사용합니다.

P50은 전체 기록의 중앙값이며, P90은 기록의 90%가 해당 시간 안에 들어오는지를 확인하는 기준입니다.

## C-4. 보드와 룬 확장 계산

기존 흔적과 겹치지 않는 기본 규칙을 기준으로 계산합니다.

| 보드 | 전체 칸 | 8칸 룬 1개 | 8칸 룬 4개 |
|---|---:|---:|---:|
| 7×7 | 49칸 | 8칸·16.3% | 32칸·65.3% |
| 9×9 | 81칸 | 8칸·9.9% | 32칸·39.5% |

7×7에서 8칸 룬 4개는 보드의 약 3분의 2를 차지합니다. 몬스터와 오염 공간까지 고려하면 배치 선택보다 공간 부족이 먼저 발생할 가능성이 큽니다. 8칸 룬은 기본 확장 범위에서 제외하고, 9×9에서도 별도 검증이 필요한 대형 룬으로만 취급합니다.

## C-8. 수익성 시나리오 참고

다음 값은 매출 예측이 아니라 팀 규모와 유료 유입 위험을 비교하기 위한 내부 민감도입니다.

ARPU는 이용자 1명당 평균 수익을 뜻합니다. IAP는 인앱 구매, IAA는 인앱 광고 수익을 뜻합니다.

| 시나리오 | D90 IAP ARPU | D90 IAA ARPU | 설치당 D90 순기여금 |
|---|---:|---:|---:|
| 보수 | $0.10 | $0.20 | 약 385원 |
| 기준 | $0.35 | $0.45 | 약 1,009원 |
| 공개 평균 합산 상단 | $1.34 | $0.55 | 약 2,280원 |

계산에는 인앱 구매 수수료 15%, 결제·분석·지원 변동비 준비율 10%, 계획환율 1달러당 1,500원을 적용했습니다. 세금, 환불, 고정비, 유료 유입비는 포함하지 않았습니다. IAP와 IAA 공개값이 동일한 하이브리드 코호트라는 보장이 없으므로 상단값을 일반 목표로 사용하지 않습니다.

| 현재 제품화 구조 | 기간 | 비용 산정 상태 |
|---|---:|---|
| 핵심 개발·기획 1명 | 선정 후 최대 6개월 | 본인 담당 |
| 아트 외부 인력 1명 | 제작 범위에 따라 계약 | 견적 확인 필요 |
| 사운드 외부 인력 1명 | 제작 범위에 따라 계약 | 견적 확인 필요 |
| 외부 테스트·기기 QA·마케팅 | 출시 단계별 집행 | 범위와 견적 확인 필요 |

현재 계획은 3~6명의 상시 풀타임 팀을 전제로 하지 않습니다. 외주 견적과 지원금 집행 기준이 확정되기 전에는 총 제작비와 손익분기 설치 수를 확정값으로 제시하지 않습니다. 높은 수익을 예상한다는 결론보다 6개월 내 출시 가능한 범위, 높은 유기적 유입 비중, 검증된 광고 생애가치가 갖춰졌는지를 먼저 판단합니다.

## C-9. 지표 판정 구간

| 지표 | 초기 기준 |
|---|---|
| 실패 후 재시도 | 실패 후 10분 이내 재시도 여부 |
| 최초 세션 조기 이탈 | 최초 실행 후 10분 이내 세션 종료 |
| 초기 유지 | D1·D7 잔존율 |
| 세션 시간 | 평균과 함께 P50·P75·P90 확인 |
| 보스 | 변형별 클리어·포기·재시도 비교 |
| 도구 | 사용 가능 상황 대비 사용률과 같은 시도 클리어율 |

공개 벤치마크가 없는 클리어율, 도구 사용률, 재시도율은 프로토타입에서 직접 기준을 만듭니다.

D1과 D7은 설치 후 각각 1일째와 7일째 다시 플레이한 이용자의 비율입니다.
